# 偏差、简化与限制

## A. 当前可确认已实现

1. 输入维度由配置控制，toy 默认 `d_x=64,M=128`。
2. 分组、均值 query、128→32 codec 投影实际执行了数值变换。
3. profile 生成器实际生成 13 个确定性 profile，并检查长度、掩码和 hash。
4. QPSK、AWGN、硬判决和软信息擦除掩码均有代码及测试证据。
5. 小规模 LP 使用 `scipy.optimize.linprog`，有 3 个手工用例。

## B. 偏差与未完成项

### D01

- 原方案要求：使用正式实验方案定义的完整算法和评价标准。
- 当前实现：仓库未提供可识别的正式实验方案，只有 toy 配置、代码和测试。
- 差异：无法确认论文级方案是否实现。
- 原因：当前目录没有方案文档或正式数据入口。
- 对结果的影响：只能验证接口和 toy 行为。
- 未来需要如何补齐：提供正式方案、数据划分、baseline、样本规模和评价脚本。

### D02

- 原方案要求：母码/LDPC 参数与角色 profile 的 `q_k,n_k` 一致。
- 当前实现：配置中母码 `k=16,n=32`，profile 最大 `q_k=256,n_k=1264`；profile 编码另用 `P_k` 直接计算校验位。
- 差异：profile 路径不是统一 32 位母码 LDPC 码的完整实现。
- 原因：toy 阶段采用按 profile 的固定线性 parity 投影。
- 对结果的影响：可验证 8192 位长度和 profile parity，但不能宣称完成正式 LDPC 母码实验。
- 未来需要如何补齐：定义统一可扩展的码长、校验矩阵、编码和译码接口。

### D03

- 原方案要求：每次实验保留完整 raw→processed→table/figure 链。
- 当前实现：没有历史 raw 结果、处理脚本、表格或图表。
- 差异：结果链仅由本次审计入口生成的最小 JSON 证据组成。
- 原因：项目是 toy 接口项目。
- 对结果的影响：没有论文级结果可追溯。
- 未来需要如何补齐：增加正式实验入口、原始结果格式、处理脚本和图表脚本。

### D04

- 原方案要求：确定性测试比较完整关键状态/指标。
- 当前实现：已有固定 seed 信道测试；审计入口比较最小链路的关键形状、比特和软值 hash。
- 差异：未比较正式训练状态、动作序列或正式 metrics。
- 原因：当前项目没有这些状态或正式实验。
- 对结果的影响：确定性结论只适用于 toy 链路。

### D05

- 原方案要求：配置成为单一可信来源。
- 当前实现：`toy`、`model`、`input` 中重复保存 `d_x`、`M` 等字段，部分模块读取不同段。
- 差异：存在配置分叉风险。
- 原因：历史重构遗留。
- 对结果的影响：修改一个字段可能不能影响所有模块。
- 未来需要如何补齐：统一配置 schema，并增加冲突字段检查。

## C. 当前环境无法验证

- 未发现真实无线/硬件信道或外部数据，因此无法验证实际信道性能。
- 未发现 GPU/CUDA 目标，因此无法验证 GPU 行为。
- 未发现正式方案规定的 sample 数、seed 数、baseline 和显著性统计，因此这些项目为 `NOT RUN`，不是通过。
